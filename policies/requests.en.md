# Requests

Last updated: 2026-11-18.

## What can be requested

- Correction or removal of an entry about oneself.
- A change of how a name is shown, or its removal.
- Notification of purpose, disclosure, correction, addition, deletion, stop of use, erasure, or stop of provision to third parties, of retained personal data.
- Removal of one's personal data.
- Removal of content that harms one's reputation or credibility.
- Removal of content that infringes one's rights.
- Withdrawal of consent to giving an issue to a language model.
- Report of conduct against the code of conduct.
- The operator's address.
- Ask for a private answer.

There is no fee.
Requests are received in the same way whatever the requester's country of residence or nationality.
Japanese and English are both accepted.

## How to request

A request is made by opening an issue with the [request form](https://github.com/cpsbvbng26-dotcom/research-collaboration/issues/new?template=request.yml).
It states which entry is concerned and what is asked.
The form asks that the personal data itself not be copied, only where it is.
The GitHub form is the only channel for requests.
No new contact details were created for this repository.
An agent may make a request.
In that case, the form asks for one line from the person's own GitHub account saying that the agent acts for them.

## Requests that cannot be made in public

When there is a reason not to write in public, the kind "Ask for a private answer" is chosen in the form and the other fields are left empty.
The issue then shows only the GitHub account name, the title and the kind.
The operator answers privately only when the requester has made a contact public on their own GitHub profile, and answers to that contact.
A person without such a contact can receive the answer by making a contact public on their own profile for a while.
Otherwise, the answer is given in the issue, without personal details.
A request for the operator's address follows the same route.
How to report a security issue is in [SECURITY.md](../SECURITY.md).
That route is the same as in the operator's other repositories, and was not created for this one.

## After a request

The operator aims to answer each request within 7 days.
Where the harm is serious, as with exposed personal data, the entry is taken down before anything is decided.
An entry that harms another person's reputation or credibility is also taken down before anything is decided.
If a takedown turns out to be wrong, the entry is restored and the writer is told in the issue.
A change in how a name is shown, or the removal of a name, is made whatever the reason.
Disclosure is made in the way requested.
When an electromagnetic record is requested, an electromagnetic record is given.
When a request is met, what was done is reported without delay.
When a request is not met, the reason is given.

## What cannot be removed

Earlier versions of the repository remain unless its history is rewritten.
Copies already made by others are outside the operator's reach.
When something must be removed from the history, the operator asks GitHub to remove it.
A name printed in a draft already published changes only through the procedure of the venue that published it.
