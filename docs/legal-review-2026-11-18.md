# 法令の点検の記録

最終更新：2026-11-18。

マージの前に、規程を読む人が誤りを探す側に立って、規程を読み直しました。
条文を取り寄せ直して照らし、言い過ぎ、足りない頁、日本語と英語の食い違いを探しました。

## 条文の取り寄せと照合

条文は、e-Gov 法令 API の条の口（`articles`）から、2026-11-18 に取り寄せました。
法令の番号は、運営者のほかのリポジトリの `verification/statutes.json` から取りました。
労働基準法と労働契約法の番号は、同じ API の法令の一覧から取りました。
照合は、互いに独立した次のやり方で行いました。

| やり方 | 結果 |
| --- | --- |
| `node tools/statutes.js`。条の口から取り寄せ直し、記した sha256 と比べる | すべて記した値と同じ |
| 法令の全文の口（`lawdata`）から法令を丸ごと取り寄せ、本則から同じ条を切り出して、写した文と比べる | すべて一字一句同じ。法令名も一覧と同じ |
| 運営者のほかのリポジトリが前に取り寄せた同じ条の文と比べる | 個人情報保護法の条と民法の条は、どれも一字一句同じ。著作権法と労働法の条は、ほかのリポジトリに無い |
| `node verification/check.js`。頁に引いた句が、写した文にそのまま現れるか | すべて現れる |

GitHub の利用規約は、github/site-policy の、そのファイルに触れた最後のコミットを、リポジトリの履歴から読みました。
引いた句は、そのコミットの文にそのまま現れました。

## 見つけたことと直したこと

| 見つけたこと | 直したこと |
| --- | --- |
| 個人情報の取り扱いに、運営者のアカウントが二段階認証を使っていると書いていた。作業の環境からは確かめられない | 文を外した |
| 名称と権利に、商標を調べない理由として、特許庁のデータベースに届かないと書いていた。J-PlatPat には届いた | 理由を外し、名を出どころのしるしとして使わないことを書いた |
| 著者と貢献に、CRediT の一覧の頁へのリンクを置いていた。作業の環境から届かず、確かめられない | リンクを外し、CRediT の語を使うことだけを書いた |
| 「どの様式も、書く欄より前に利用目的を書く」と書いていた。正本の写しの誤りの知らせの様式は、利用目的を書いていない | このリポジトリのために作った様式に限った。検査が、その様式の最初の欄を見る |
| 漏えいなどが起きたときの節が無かった | 個人情報保護法第26条を取り寄せ、法令の整理と個人情報の取り扱いに節を足した。委員会規則は取り寄せていないので、どの事態が当たるかの結論は出していない |
| ライセンスの頁に、著者全員の合意でライセンスを変える道を書いていた。CC BY 4.0 で出せない場に出さない文と食い違う | 変える道の文を外した |
| DCO を使わない理由の後に、同意の欄が同じことを確かめると書いていた。欄が確かめるのは、そのライセンスで出す権利だけである | 欄が確かめる中身に合わせた |
| 求めの頁が、窓口は GitHub だけと書いていた。正本の写しの SECURITY.md は、運営者の ORCID の記録の宛先を入口にしている | 求めの窓口は様式だけと書き、SECURITY.md の入口は運営者のほかのリポジトリと同じ既存のものだと書いた |
| 求めの頁の種類の並びと、求めの様式の選びが、日英ともに食い違っていた | 様式に合わせ、検査が一字一句で照らす |

## 結論を出していないところ

次のことは、法令の整理の頁で、結論を出していないと書いています。

- 運営者が個人情報取扱事業者に当たるかどうか。
- issue の様式に書かれたものが、個人情報保護法第21条第2項の書面に当たるかどうか。
- issue の公開が、運営者による第三者への提供に当たらないという扱いが正しいかどうか。
- issue の中身が、個人情報保護法第28条の個人データに当たるかどうか。
- どの事態が、漏えいなどの報告の委員会規則に当たるかどうか。
- ある稿が共同著作物に当たるかどうか。
- 協力のどの行いが、民法第5条の法律行為に当たるかどうか。
- ある協力の関係を、労働基準法と労働契約法のもとでどう位置づけるか。
